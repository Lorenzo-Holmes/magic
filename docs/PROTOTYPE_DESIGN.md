# 《我欲飞升》实现基线 v2.1.0 · 山海行旅

## v2.1.0 行旅与界面约定

主存档 v16，旧 v15 补独立 journey 状态并保留经典突破；浏览器新局启用行旅根基。引擎 createRun 的无选项调用仍为经典模式，用于旧调用方和兼容回归，新模式必须显式传入第三参数 {journey:true}。根基按境界记录，同境同路线只在至少两次应对成功后首次结算；问道给三点，其余给两点，突破需要二到四点。

六地、十八路线、五十四段叙事，四种工具对应四属性。出行耗三盘缠及一个行动年的实际寿元，途中每段耗一至二份粮。安全应对也可能失手，装备无法替代全部属性；主动撤回保留八成，被迫返回保留四成，伤势可药疗或静养。晚年不足远行时明确回到最后闭关与本世结局，不能卡在不可操作的准备页。

行旅随机值由本世 seed、行程序号、路线与段次确定；预览、刷新与导入不重抽或再次结算。主随机流不变，途中冻结准备与其他玩法操作。资源、阅历和历史有上限，保留最近十八份结算。新风险策略仿真与经典 6000 局兼容仿真分别报告。

四个一级页面和本地生成的水墨位图取代旧导航与发光视觉层，事件和地图交互仍为 HTML。详见 REDESIGN-v2.1.0.md 与 ART-v2.1.0.md。

## v2.0.0 世界法则约定

主存档 v15，旧 v14 仅补 world:null。必须完成仙界进化正式结局且已有本世大道，才可主动创世；不会替玩家自动进入。世界独立保存五个配置：灵气（三选一）、主修体系（三选一）、核心大道（此世已创之道）、世界风险（三选一）、传承（三选一），共 81 种合法组合。创世后锁定这些参数与大道规则，不增加冗余货币或实时大型模拟。

每纪依次出现修行、灾劫、传承三类事件，各有顺应法则或收束稳固两种选择。灵气和主修体系改变生机，风险改变劫势，传承改变生机/秩序分配，核心大道的守护或参悟性质参与结算。选择前显示具体变化；世界生机与秩序始终处于 0～100。相同 seed、五法与选择得到相同摘要，世界不消耗本世 RNG。

三段事件后进入「我即天道」正式结局，结局文案对应实际世界状态；可继续下一纪，也可返回仙界。纪元按十进制整数字符串递增，避免浮点丢失；史册最多保留 24 条，每条只有事件、选择、纪元与前后状态。历史投影只保留本世大道名称、源 seed 与短摘要，不复制人物背包或完整存档。凡界成就与仙界状态在世界操作前后保持一致。

新世界入口为 world.js，纯呈现入口为 world-ui.js。重复创世、过期事件、提前继续、非法五法、未知规则、来源冲突、越界数值和损坏史册都会被拒绝。已开启世界刷新后默认回到该天地，仍保留返回仙界和命册导入/导出入口。

## v1.12.0 自创大道约定

主存档 v14，旧 v13 只补空 dao。修行记录只在成功动作后采样，最多保留 48 段：主脉、真实行为类别、已选路线、境界与当时佩戴的装备标签。面板不采样、不消耗 RNG。连续闭关的一次自动批次只记一段决策。

元婴后至少十二段行为，最近十二段中九段主脉一致，可以主动创道。十个名称词根与八个固定规则组件确定性组合，主脉给出核心组件，行为及装备统计给出次级组件。冲突矩阵对称，剑/吞噬、肉身/神魂、气运/悟道、守一/惊雷互斥；最多两个规则。名称与规则都可由保留来源重算校验，没有动态代码或联网命名。

创道锁定本世来源，不能通过换装或再次点击重置。每条效果本世最多二至三次，直接给予有界修为或元气，不进入永久效果表。仙界继续记录真实修行并允许创道，但凡界增益不会作用于仙界。轮回重新建立空大道。次数、来源、种子与名称不一致的存档拒绝导入。

用户要求的 UI 参考升级与黑色打坐占位一并纳入本版，具体约定见 UI-v1.12.0.md。

## v1.11.0 叙事轮回约定

轮回册升级到 v3。`runHistory` 在原 seed / 结局 / 道痕来源字段之外新增人物摘要、妖王路线与三重天劫路线；`legacy.echoes` 最多 24 条，只保存已偿重要因果的来源/关系/结果；`legacy.legends` 最多 24 条，只保存一世最高阶段本命神兵与主灵兽的名称、阶段和纯文本传说。

旧 v1 轮回册仍先补齐 v2 的仙界图谱字段，再迁移到 v3；旧 v2 只建立空 legacy，不从旧历史猜测过去持有什么神兵、灵兽或因果。

同一世飞升后继续结契、进化灵兽或偿还因果时，轮回册仍会幂等更新叙事。结局计数只登记一次，同世同类传说只保留最高阶段；重新载入较早存档不会降级传说，也不会复制新的数值收益。

## v1.6.0 宗门约定

新增 `src/sect.js`，四宗固定为青云剑宗、天罡体宗、万灵吞月谷、天机道院。宗门状态是主存档 v9 的受校验子状态，记录当前归属、已谢绝宗门、传承是否解锁、一次性事件完成集合、待处理事件、宗门大事件结果和最近 20 条宗门摘要；不保存贡献币、职位、工资、签到或每日进度。

## v1.5.0 秘境约定

## v1.5.0 短局秘境约定

新增 `src/secret-realm.js`，秘境总状态为 `{ version, active, completed, history }`。首版三座秘境固定 3 / 4 / 5 层，分别覆盖凡人～筑基、金丹～化神、炼虚～大乘阶段。每一层的候选路线使用 `run seed + realm id + floor` 派生的独立 deterministic hash，UI 打开、关闭、刷新都不推进主 RNG。

每个普通层至少保留灵药或功法残页之一作为非失败路线；战斗、禁制和异象可以有更高收益与失败结果。失败只结束 `active` 秘境并结算可保留部分，不设置本世 `dead`。任何层都存在显式 `secret-exit`，退出保留已 banked 收益与一部分未保底收益。临时 `tempPower / tempGuard` 只存在于 active session，结束后随 session 一起清理。

Boss 首次完成把 realm id 写入最多三项的 `completed`，并通过已有装备系统生成唯一 `secret:<realm>:boss` 来源；重复通关不再得到首胜装备。秘境历史最多 12 条摘要。主存档 v7→v8 只补 `secretRealm=createState()`，不从旧历程猜测任何秘境完成状态。

当秘境 active 时，主 reducer 拒绝闭关、历练、突破和装备操作，只接受 `secret-*` 结算动作，避免在秘境内部借主界面改写入口战力。刷新恢复后仍停在同一层、同一候选与同一暂存收益。

## v1.4.0 确定性战斗与文字回放约定

## v1.4.0 确定性战斗与文字回放约定

新增 `src/combat.js`。战斗的随机、威胁判定、Build/装备效果仍由主状态机在玩家动作时一次性确定；战斗模块只接收明确的 `playerPower / enemy / chance / roll / damage / reward / route`，以纯函数生成固定结果和最多 10 条 `replayEvents`。表现层不得调用主 RNG，也不得在播放期间重新计算胜负。

凡界普通狩猎与三眼妖王首先接入统一战斗解析。主 reducer 在一次 transition 中提交伤害、修为、吞噬、Boss 路线及装备掉落，再把同一结果压成 `combatReplay` 写入主存档。装备系统若同一次战斗产生真实掉落，只向这份已提交回放补一个 `drop` 事件；不会让回放反向控制掉落。

主存档升级 v6→v7，仅新增 `combatReplay`。字段为 `null` 或 `{ version, id, enemy, result, events[] }`，事件数上限 10、文本长度有硬限制。刷新/导出/导入会保留同一份回放；下一次真实游戏 action 会清除旧回放。迁移旧 v6 只补 `null`，不依据日志猜测旧战斗。

UI 战录可跳过，跳过只隐藏表现层，不调用 reducer。普通动态按事件顺序在 1～5 秒内出现；`prefers-reduced-motion` 直接展示所有最终事件。R≥2 继续由既有规则保证必胜无伤；防御减伤与一次性重生仍由主引擎提交，combat 模块只描述已确定的实际结果。

## v1.3.0 Build 统一解释约定

## v1.3.0 Build 统一解释约定

新增 `src/build.js`，只依赖静态数据与凡界装备定义，不依赖主引擎的战力/随机函数，避免从 `engine.effects()` 反向形成循环。标准标签固定为剑道 / 雷霆 / 吞噬 / 肉身 / 神魂 / 气运 / 悟道 / 生存 / 爆发 / 成长；来源覆盖天命、基础属性阈值、灵根、青云剑诀、首次异变、金丹融合、已穿戴且已鉴定装备、妖王路线与天劫路线。

`evaluateBuild(state)` 是纯派生：统计标签权重后选出六条主道途标签中的主脉与辅脉，再根据公开 `SYNERGIES` 规则表激活协同。首版 15 条协同，每条都声明 `requires + effects + text`；聚合效果严格等于已激活规则逐项相加。主引擎只读取这一聚合结果，不在其他位置加入同名隐藏倍率。

协同效果保持小幅、可解释，继续复用已有 `power / bossPower / devour / devourHeal / guard / explore / mind / cultivate / xp / swordPower` 字段。卸下装备会使来源消失，下一次评估立即撤销由该装备补齐的协同，不留下后台状态。由于 Build 本身不持久化，本版不提升主存档版本；v6 存档仍完整兼容。

命册 UI 通过“来源 → 协同 → 当前效果”显示推导关系，并列出主脉、辅脉、标签得分与全部来源。打开/关闭该界面不修改任何游戏字段或 RNG。原 `meta.js` 六大道途识别继续保留作为轮回与称号语义层，Build 系统作为更细粒度的实时战斗/事件解释层，二者不互相写状态。

## v1.2.0 装备与本命神兵约定

凡界新增 `src/equipment.js`，作为主存档 v6 的受校验子状态。四槽固定为兵器 / 法宝 / 法衣 / 佩饰，行囊最多 12 格；当前包含 24 件基础装备和 3 条 × 3 阶段的本命神兵。装备效果复用主引擎已经支持的 `power / guard / cultivate / explore / devour / swordPower / bossPower / bone / insight / luck / mind` 等字段，不建立第二套战斗数值体系。

装备掉落不调用 `engine.random()`：`seed + sourceKey + kind + realm + route` 经独立确定性哈希生成。`seenSources` 最多保留 64 个不可重复来源键，同一来源不会因刷新、重复操作或导入重领。妖王、天地印证与天劫为高价值来源；普通历练与狩猎允许按哈希命中/落空。行囊满 12 件后，新的成功掉落直接折算成器蕴，不扩容。

装备必须先鉴定才可穿戴；鉴定无资源成本。归炉把未穿戴装备转成器蕴；温养固定四段「初炼 / 温养 / 通灵 / 圆满」，每段确定成功，不存在耐久、强化失败或 `+N` 显示。本命神兵只在已鉴定并穿戴于兵器槽时从实战、妖王和天劫积累历练，阶段 1→2 与 2→3 分别需要固定阈值，达到后由玩家主动蜕变。

三条本命神兵线为：剑道 `青锋剑胚 → 雷狱剑 → 斩界天锋`；吞噬 `噬灵幡胚 → 饕餮玄幡 → 吞天魔幡`；肉身 `镇岳尺胚 → 地脉镇尺 → 擎天神岳`。妖王路线会优先匹配剑道 / 吞噬 / 肉身，其余路线由同一确定性哈希选择。神兵蜕变复用表现层重大事件，不额外推动主 RNG。

凡界四槽与仙界 `evolution.slots` 的肉身 / 血脉 / 神魂 / 神通 / 法则五槽在数据模型、UI 和效果读取上完全隔离。v5→v6 迁移只建立空装备状态，不回填装备、来源或器蕴；旧结局与仙界子状态不受影响。

## v1.1.0 表现层约定

守界胜利后必须手动踏入下一界。世界边缘完成后给出正式结局，之后才可开启无尽。每次跨界把尺度乘四，当前炼化清零，五槽保留。无尽层数和指数用十进制字符串/BigInt 运算；势能采用 12 位有效数字加指数，不转为超大 JS Number。主操作版本超过小整数范围后转字符串精确递增，继续阻止重复点击领取。仙界日数/吞噬显示计数在极高计数时饱和，但无尽层数继续增长，气运周期单独存储，因此不会因饱和停止奖励周期。

失败只终止本界操作，可保留世界与五槽重整仙躯、重修本界炼化；不回退 RNG、不补发失败奖励。安全缓炼、碎片凝聚和调息保证低资源恢复途径。状态输入严格限制阶段/槽位/候选/配方/数量级，历程与候选队列有固定上限。

## 1. 本版目标

v0.5.0 完成了从凡人到飞升的凡界主线，v0.5.1 用七阶段境界背景解决长线游玩时世界缺少视觉层级的问题。v0.6.0 处理下一项核心问题：**第一世结束以后，玩家为什么还要再开一局。**

本版不扩大仙界，不增加宗门、炼丹、炼器或付费系统。它在现有完整主线之外增加一层轻量跨局结构：

```text
本世真实选择
→ 流派识别
→ 图谱与称号记录
→ 三选一凝练道痕
→ 下一世一次性继承
→ 开局流派保底 + 对应天劫额外路线
→ 道痕被消费
```

设计原则是“提供新的开局方向，而不是永久堆叠战力”。凡界首遇妖蟒、筑基复仇、金丹融合、妖王和天劫的原有压力结构必须继续成立。

`基础战力 × 境界倍率 × 境界进度 × (1 + 全局增益) × 元气系数`

- R < 0.55：十死无生，不允许正常送死；
- 0.55～0.85：凶险；

- 1.20～2.00：优势；
- 2.00～3.00：碾压；
- R ≥ 3：蝼蚁。

R ≥ 2 必胜且不损失元气。轮回道痕不参与该公式。

## 7. 轮回道痕

### 7.1 候选生成

飞升或死亡后，从六类路径分数中取前三名作为候选。候选显示契合分、判定依据、下一世影响和对应天劫用途。玩家只能选一枚；重新选择会替换，而不是叠加。

### 7.2 当前六枚道痕

| ID | 道痕 | 开局影响 | 天劫阶段 |
| --- | --- | --- | --- |
| `devour` | 噬界残痕 | 至少一张吞噬天命 | 天门终劫 |
| `sword` | 剑心余烬 | 至少一张剑道天命 | 天门终劫 |
| `body` | 不灭骨印 | 至少一张肉身天命 | 九霄雷劫 |
| `soul` | 照幽灵纹 | 至少一张神魂天命 | 问心魔劫 |
| `fortune` | 天命余辉 | 至少一张气运天命 | 天门终劫 |
| `insight` | 悟道残卷 | 至少一张修炼天命 | 问心魔劫 |

### 7.3 开局保底

带痕创建新存档时，先照常生成八张天命并保留第一张玄品以上保底。如果八张中没有对应流派，替换最后一张普通候选为该路径天命。重抽继续执行同一规则。

该规则只保证“至少出现一项”，不指定具体单卡，不提高稀有度，也不自动选择。

### 7.4 一次性消费

轮回册中的 `nextTrace` 在新存档创建成功后清空，道痕 ID 写入新存档的 `carriedTrace`。该存档整个生命周期都能识别这枚道痕，但它不会自动传到下下一世。新一世结束后必须重新从本世候选中凝练。

### 7.5 天劫路线

每枚道痕只在配置的天劫阶段追加一个可选路线。成功采用后，路线 ID 写入 `tribulationRoutes`，供称号、图谱和命册使用。道痕路线与普通专属路线采用同一战力判定，不保证无条件成功。

## 8. 连续闭关

`cultivate-to-ready` 是一项显式玩家操作，不是后台自动运行。它循环使用原有闭关逻辑，并在以下条件停止：

1. 强制赤鳞妖蟒遭遇出现；
2. 当前境界修为达到阈值；
3. 下一次闭关会触及寿元上限；
4. 状态进入死亡、阻塞事件、突破或其他不可闭关阶段；
5. 安全上限 64 次循环。

连续闭关不自动突破、不解决事件、不选择天命、不挑战妖王、不执行天地印证，也不进入渡劫选择。多次闭关会合并当前事件说明，并在日志中保留汇总。

## 9. 原有关键因果

### 9.1 赤鳞妖蟒

首次妖蟒固定 150 战力。正常开局玩家约 20～40 战力，只能逃生，并由此获得基础吞灵诀。筑基后妖蟒仍为 150，玩家可以直接吞噬或镇杀后炼化遗蜕，两条路线都进入首次异变。

### 9.2 金丹融合与三眼妖王

首次异变必须带入金丹并形成三项融合候选。三眼妖王固定 24,000 基础战力，至少完成两处金丹机缘且存在可行路线后才能挑战。本版额外记录实际破局路线，但不改变旧有路线条件。

### 9.3 天地印证与三重天劫

元婴、化神、炼虚、合体、大乘每境至少完成一次世界尺度事件才能破境。大乘以后依次经历九霄雷劫、问心魔劫和天门终劫。三劫全部完成才设置 `ascended=true`。

## 10. 正式终点

飞升页继续明确显示“天门已开”和“你已飞升”，保留旧敌 150、玩家数百亿战力、仙界噬灵虫约玩家 1.7 倍的三段反差。

仙界噬灵虫仍是彩蛋，不是可操作的仙界主线。v0.6.0 的新增终点操作是凝练道痕和查看图谱，而不是继续堆叠未完成关卡。

轮回册独立于本世存档，包含：

- 已结束与已飞升次数；
- 八类图谱发现集合；
- 最近 50 世摘要；
- 下一世待继承道痕及来源种子。

本世存档与轮回册可分别导出和导入。导入本世不会覆盖跨局发现；导入轮回册不会篡改当前角色。损坏、未知 ID、重复发现和越界统计会被验证器拒绝。

## 13. 视觉系统

v0.5.1 的七阶段背景完整保留：黑风岭、凌云之巅、丹霞悬境、诸域云上、界外星海、九霄劫天和天门彼岸。妖蟒、融合、妖王、高阶事件、渡劫与飞升继续使用独立气氛覆盖。

新增界面沿用命册视觉：道途提示是窄幅批注，图谱使用可折叠册页，道痕候选使用三列/移动端单列结构。没有改造成手游大厅或卡牌抽奖界面。
