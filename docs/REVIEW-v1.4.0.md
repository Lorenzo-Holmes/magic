# v1.4.0 视觉与系统复核 · 九州历练

## 目标

把瞬时战斗结果升级为短促文字战录，同时严格维持“结算一次、表现多次”的边界。动画关闭、跳过、刷新和重复打开都不得改变最终存档。

## 系统复核

- `src/combat.js` 为纯解析模块，不读取或推进主 RNG。
- 同一输入得到完全相同的胜负、伤害、奖励和 `replayEvents`。
- R≥2 继续必胜且实际伤害为 0。
- 普通狩猎与三眼妖王由主 reducer 一次提交结果后才生成回放。
- Build/妖王路线只作为已确定的 `trigger` 文本进入回放，不在动画时重新计算。
- 装备掉落由原装备观察器确定；回放只显示已经真实发生的掉落。
- `combatReplay.events` 最多 10 条；下一次真实操作清除旧回放，localStorage 不持续累积战斗日志。
- v6→v7 只补 `combatReplay: null`，不伪造历史。

## UI 复核

- 战录固定覆盖层不阻塞主状态持久化；「略过」只关闭覆盖层。
- 刷新后重播相同 replay id，存档、RNG、奖励逐字节不变。
- reduced-motion 直接显示全部事件最终帧。
- 320 / 360 / 390 / 430 / 768 / 1280 六宽度无横向滚动；跳过按钮保持至少 44px 触控尺寸。
- 战录控制在 1～5 秒，不演变为长回合制战斗。

正式证据以 `output/playwright/v1.4.0/latest-isolated-run.json` 指向的隔离目录为准；只有 combat 专项、完整凡界、仙界、五槽与 release 校验全部绿色后才允许发布。
