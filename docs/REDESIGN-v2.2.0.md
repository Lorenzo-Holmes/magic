# v2.2.0 洞府山海：场景化 UI 重构

## 背景

v2.1.0 已经把旧版高饱和、发光和大面积渐变卡片收敛为纸色水墨界面，但主修行页依然主要由“状态卡 + 事件卡 + 三个等宽动作按钮”构成，信息结构仍偏网页面板。对《一念逍遥》Android 安装包进行静态 UI 结构分析后，可以确认其核心体验来自“场景优先、功能入口空间化、独立玩法场所、全屏关键演出”，而不是单纯的按钮皮肤。

本版本只借鉴这种信息架构，不复制参考游戏的图片、Prefab、字体或其他美术资源。正式页面继续使用《我欲飞升》已有原创水墨资源和 HTML/CSS 控件。

## 本版四个 P0

### 1. 洞府场景主页

- 修行页中央改为完整草庐场景，不再把插画塞在状态卡内部。
- “闭关 / 山海 / 寻机缘”改为空间热点，直接落在场景不同位置。
- 当前目标作为场景底部题签，而不是独立大卡片。
- 遭遇发生时场景压暗并缩短，事件纸面覆盖在场景下沿，保持“在这个地方发生了事”的连续感。

### 2. 游戏式底栏 HUD

- 一级入口固定为：修行 / 山海 / 行囊 / 人物。
- 桌面端同样把一级导航放到主内容下方，右侧只保留轻量此生手记。
- 移动端底栏固定在可滚动主内容之外，避免长页面把导航推走。

### 3. 人物场景页

- 人物页不再使用七个同构列表项。
- 中央为无具体面貌的黑色人物剪影。
- 命册、神兵、大道、灵兽围绕人物布置，形成装备/养成空间感。
- 根骨、神识、悟性、气运放在人物舞台底部。
- 宗门、人生、因果、轮回、图谱降为二级横向入口。

### 4. 全屏破境演出

- 继续复用既有表现层，不修改结算和 RNG。
- `breakthrough` / `ascension` major event 改为全屏场景：升仙背景、光柱、圆形道纹和大字号境界名称。
- `prefers-reduced-motion` 仍禁用动画。

## 实现边界

- 不改变玩法数值、存档格式、事件随机、行旅结算、装备掉落或突破签池。
- 不依赖第三方前端框架。
- 不把《一念逍遥》APK 中拆出的任何 PNG / SpriteAtlas / Prefab 放进正式包。
- 新增 `src/scene-ui.css` 作为 v2.2 场景化覆盖层，尽量避免继续累积到旧主题文件。

## 参考安装包结构得到的设计证据

静态分析确认参考客户端为 Unity 2022.3.34f1c1，UI 主要由 Prefab、SpriteAtlas、Texture、Lua 界面逻辑组成。定向解析的关键页面表现出以下规律：

- HUD：底部一级功能入口，而非顶部 Dashboard 菜单。
- 洞府：功能入口直接分布在空间坐标中。
- 药园：整屏场景 + 前后景竹林、水波、鱼、云层 + 底部操作区。
- 人物：角色主体居中，装备位环绕，属性集中到底部。
- 世界：可滚动大地图而非地点卡片列表。
- 技能：树形画布和环境层共同构成页面主视觉。
- 突破：1080×1920 级别的独立全屏演出结构。

这些证据只用于建立本项目自己的场景化 UI 原则。

## 验收重点

- 320×568、360×800、390×844、430×932 移动视口无横向溢出。
- 三个修行热点均可触发原有 action，不重复结算。
- 遭遇状态下不显示普通行动热点。
- 人物页四个主要入口和五个二级入口全部可点击。
- 底栏在移动端不随主内容滚走。
- 破境表现层不改变 `state.revision` 之外的既有游戏结算流程。
- 全量 Node 测试、最终仿真、浏览器 QA 和生产包体检查继续通过。
