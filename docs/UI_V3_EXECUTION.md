## D 阶段的技术验收

用独立开发入口或 build-time renderer 选择试验新 UI。必须兼容现有双击 index.html 的使用方式；JSON 配置打包为本地脚本对象或静态生成，不依赖 file:// fetch 成功。

WindowManager 生命周期采用本项目自定义约定：prepareAssets → mount → bind → update → suspend/resume → unmount/dispose。所有监听、动画和计时器在 dispose 中释放。

上句是最终目标，不是当前 API 清单。当前实现采用同步 HTML 替换渲染：render → commit(bind/update) → deactivate(cleanup/dispose)。同窗口重绘也释放旧绑定；离开 V3 到旧章节时显式 deactivate；错误不再被空 catch 吞掉。尚无持久 DOM 窗口缓存、异步资源加载器、完整 mount/suspend/resume 或 Unity 锚点解析器。

GameAdapter 只调用现有 transition/persist；首轮从 app.js 提取接口，不能复制规则或另立存档。按当前代码逐项记录副作用：教程标记、轮回观察、音效解锁、反馈、导入备份、重要阶段导航。

建议最少锚点单测：

- 800×1732 父容器，全 stretch + zero sizeDelta 得到同尺寸。
- HUD bar 得到 [left=0, top=1602, width=800, height=130]。
- 左上锚定，position=(20,-30)、pivot=(0,1)、sizeDelta=(100,60)，得到 [20,30,100,60]。
- 中心锚定，position=(0,0)、pivot=(0.5,0.5)、sizeDelta=(100,60)，得到 [350,836,100,60]。
- 嵌套父节点、bottom-safe-area、非等比屏幕、LayoutGroup 未支持时的显式拒绝。
- 64 位 pathID 字符串往返保持一致。

设计单位与 CSS px 分开断言。任何 44 px 触控要求都指实际 CSS px，不是 800 宽设计画布的单位。
