# 《我欲飞升》v1.1.0 → v2.0.0 产品扩展路线

## 0. 文档目的

本路线以当前真实 `v1.0.0` 为唯一基线，供后续会话连续实现，不重新设计已经稳定的凡界、轮回、仙界和无尽诸天。

目标不是继续堆菜单，而是把《我欲飞升》收束成：

> **轻量文字修仙 + 无限进化 + Build 构筑 + 本命神兵 + Roguelite 历练 + 因果轮回 + 规则级飞升。**

每个版本都必须做到：即使后续版本尚未实现，该版本本身也是完整、可玩、可回退、可发布的稳定版本。

## 2. 总体设计原则

### 2.1 一屏只回答四个问题

主界面优先让玩家看到：

1. 我现在是什么境界；
2. 我现在有多强；
3. 下一步最值得做什么；
4. 我刚刚获得了什么成长。

背包、图鉴、宗门、炼丹、因果等全部属于二级内容，不允许共同争夺首页首屏。

### 2.2 平常克制，节点爆发

普通点击保持轻反馈；以下节点才允许明显动画和强音效：

- 稀有掉落；
- 本命神兵进化；
- 大境界突破；
- 金丹融合；
- 妖王击破；
- 雷劫；
- 飞升；
- 大道诞生；
- 世界规则改变。

### 2.3 装备必须改变玩法

禁止把装备系统做成纯“攻击 +100、强化 +12”。

装备至少要影响以下之一：

- 触发方式；
- 流派标签；
- 战斗路线；
- 修炼方式；
- 秘境选择；
- 资源转换；
- 本命进化条件。

### 2.4 无限进化不等于无限堆存档

所有无限内容都必须有硬上限或滑动窗口：

- 背包有容量；
- 历程有保留上限；
- 因果记录只保留关键节点；
- 战斗演出不把完整日志永久写入；
- 世界历史只保留摘要；
- 超大数值继续沿用现有有限精度数量级表示。

### 2.5 不增加“伪内容”

不做：

- 签到；
- 每日任务；
- 邮箱；
- 红点矩阵；
- 月卡式资源界面；
- 广告奖励；
- 付费抽卡；
- 装备耐久；
- 十几个装备槽；
- 六七种强化货币；
- 3D 角色或重型战斗动画。

## 4. v1.1.0「灵台焕新」

### 目标

不改变核心战斗数值，重做视觉优先级和关键反馈，让现有内容先达到正式小游戏的触感。

### 必做

- 首页重新排序：境界 > 修为/战力 > 当前事件 > 主操作 > 辅助信息；
- 降低通用卡片数量，减少 Dashboard 感；
- 现有七阶段背景增加更清晰的前景/雾气/灵气层级，但仍使用 CSS/SVG；
- 普通奖励采用短促数字跳字；
- 稀有天命/异变/融合/装备以后统一使用品质视觉令牌；
- 大境界突破增加 1.5～3 秒不可叠加的短演出；
- 雷劫、飞升、本命进化预留统一“重大事件演出层”；
- 扩充现有 Web Audio 反馈，而不是加入 MP3；
- 完整支持 `prefers-reduced-motion`；
- 320/360/390/430 px 竖屏必须无横向滚动。

### 不做

- 不新增玩法系统；
- 不重算战力；
- 不修改轮回道痕效果；
- 不引入外部字体、图片 CDN、MP3。

---

## 5. v1.2.0「本命神兵」

### 目标

建立凡界到仙界都能理解的装备系统，但与现有“仙界五槽进化”明确分层：

- **装备**：本世战斗与 Build 的载体；
- **仙界五槽**：飞升后的高阶进化器官/法则体系。

二者可以产生协同，但不能混成一套槽位。

### 四个槽位

1. 本命兵器；
2. 法宝；
3. 法衣；
4. 灵饰。

### 核心循环

`历练掉落 → 鉴定 → 穿戴/炼化 → 本命兵器积累 → 进化 → 解锁规则词条`

### 约束

- 背包默认最多 12 件，避免存档膨胀；
- 同槽只生效一件；
- 无耐久；
- 无强化 +N；
- 无随机十层词条；
- 品质只影响候选池与词条复杂度，不允许纯指数碾压主线；
- 本命兵器必须有 3～5 个阶段性进化节点；
- 旧装备可以炼化为本命成长，不制造无意义垃圾堆积。

---

## 6. v1.3.0「万法归一」

### 目标

把目前六大道途从“解释层”升级为“可构筑但不锁职业”的规则层。

### Build 来源

- 先天天命；
- 前世天命；
- 属性；
- 灵根；
- 首次异变；
- 金丹融合；
- 本命兵器；
- 其他装备；
- 仙界法则；
- 五槽特性。

### 设计

每个内容提供少量标准标签，例如：

- `sword`
- `thunder`
- `devour`
- `body`
- `soul`
- `fortune`
- `insight`
- `survival`
- `burst`
- `growth`

协同必须可解释。例如：

> 剑心通明 + 雷剑类本命兵器 → 雷剑触发率提高，而不是隐藏增加一段未知战力。

界面必须显示“为什么形成这个 Build”。

---

## 7. v1.4.0「九州历练」

### 目标

保持文字游戏定位，把当前战斗的瞬时结果升级成 1～5 秒可跳过的文字战斗演出。

### 原则

- 战斗结果先由确定性引擎得出；
- 表现层只回放事件，不在动画时间轴重新掷随机数；
- 高战力碾压仍然必须稳定碾压；
- 动画关闭时立即显示同一个结果；
- 刷新页面不能重复领取掉落。

### 回放示例

`敌人出现 → 本命词条触发 → 攻防交换 → Build 触发 → 斩杀/败退 → 奖励`

保留短促，不做传统回合制长战斗。

---

## 8. v1.5.0「秘境降临」

### 目标

增加 3～7 分钟一轮的可复玩 Roguelite 支线。

### 基本结构

每座秘境 3～5 层，每层 2～3 个路线节点：

- 战斗；
- 灵药；
- 商人/交换；
- 功法残页；
- 陷阱；
- 神秘事件；
- Boss。

### 风险原则

- 必须有“现在退出并保留部分收益”的路径；
- 高风险节点必须提前给出可感知风险；
- 不允许秘境失败导致整世存档不可恢复；
- 秘境内临时增益离开后清理；
- 真正获得的装备/发现/因果才写回本世或轮回册。

---

## 9. v1.6.0「宗门时代」

宗门是事件与传承系统，不是经营后台。

首版宗门控制在 4 个左右，每个宗门只需要：

- 一个核心流派偏好；
- 一个宗门被动；
- 一条 3～5 节事件链；
- 一个宗门大事件；
- 一个离宗/叛宗/护宗选择。

不增加每日贡献、工资、复杂职位树。

---

## 10. v1.7.0「天命人生」

当前出身不再只是开局标签，而要在后续境界触发至少两次相关事件。

例如：

- 修仙世家 → 族中试炼 / 旧族因果；
- 没落皇族 → 故国遗迹 / 王朝选择；
- 魔道遗孤 → 身份暴露 / 血月旧事；
- 山野凡民 → 故乡灾祸 / 凡尘牵挂。

每条人生链必须可以拒绝，不强迫玩家按“职业剧本”行动。

---

## 11. v1.8.0「灵兽仙缘」

只允许一个主灵兽位。

灵兽不是收集册，而是一条长期进化树：

`幼体 → 灵兽 → 妖兽/圣兽 → 真灵 → 仙兽`

进化由材料、事件和玩家 Build 决定，允许分支，不做十只宠物排队加战力。

---

## 12. v1.9.0「丹器百艺」

### 炼丹

只保留：主药 + 辅药 + 丹火/手法 → 结果。

首版丹药服务于：

- 修炼；
- 突破；
- 恢复；
- 临时 Build；
- 特殊事件。

### 炼器

炼器主要服务本命兵器分支进化，不建立第二套独立装备强化游戏。

允许低概率“异丹/异器”，但随机必须可复现并写入存档 seed 流程。

---

## 13. v1.10.0「因果天网」

### 核心

重要选择写入轻量因果记录：

`来源 → 关系 → 强度 → 可触发阶段 → 已偿还/未偿还`

例如：

`救下青丘幼狐 → 青丘之恩 → 元婴以后可能回响`

玩家只看到已知因果，不提前剧透完整结果。

必须保证：

- 因果不是随机惩罚；
- 触发来源可追溯；
- 已结算因果不会重复领取；
- 因果总量有上限，旧的已结算记录压缩为摘要。

---

## 14. v1.11.0「百世回响」

这是对当前一次性道痕轮回的扩展，不推翻原规则。

保留：

- 道痕只服务下一世；
- 不建立永久攻击倍率树。

新增：

- 最近前世人物摘要；
- 重要因果跨世文本回声；
- 前世曾创造/持有的重要对象在后世成为传说条目；
- 某些事件根据轮回历史改变描述或选项。

跨世收益优先是“信息、路线、故事、选择”，而不是永续数值。

---

## 15. v1.12.0「大道争锋」

### 目标

玩家不再只被归类为六大道途，而可以在长期行为足够稳定后形成自有大道。

大道生成依据必须来自可核对行为统计，例如：

- 主流派；
- 常用装备标签；
- 常用战斗路线；
- 是否偏吞噬/承伤/暴击/悟道；
- 雷劫方式；
- 因果倾向。

大道名称使用预置词根组合，不调用联网 LLM。

大道效果必须由标准规则组件组合，不能动态生成不可测试代码。

---

## 16. v2.0.0「我即天道」

### 定位

v2.0.0 才允许进行“规则级”重大升级。

飞升不再只是进入更高倍率的世界。玩家可以建立自己的世界，并选择少量天地法则：

- 灵气浓度；
- 主体修炼体系；
- 一条核心大道；
- 一种世界风险；
- 一条传承规则。

世界随后根据确定性规则生成历史摘要。

过去角色可以以“古史记录、祖师、遗器、功法源头”方式投影进世界，但禁止把完整旧存档复制进新世界。

### v2.0.0 的真正结局

`我要飞升 → 我能跨界 → 我能创道 → 我能定义一方天地。`

这才构成第二阶段标题意义。

## 17. 技术路线

新增模块优先独立，不继续无限膨胀 `app.js` / `engine.js`：

| 模块建议 | 职责 |
| --- | --- |
| `src/equipment.js` | 装备目录、掉落、穿戴、炼化、本命进化 |
| `src/build.js` | Build 标签、协同、解释 |
| `src/combat.js` | 确定性战斗结果与表现事件序列 |
| `src/secret-realm.js` | 秘境状态机 |
| `src/sect.js` | 宗门配置与事件 |
| `src/life.js` | 出身/人生事件链 |
| `src/spirit-beast.js` | 单主灵兽与进化 |
| `src/crafting.js` | 炼丹、炼器、材料转换 |
| `src/karma.js` | 因果记录与延迟触发 |
| `src/dao.js` | 自创大道规则组件 |
| `src/world.js` | v2 世界法则与历史摘要 |

模块必须保持浏览器原生 JS、无运行时第三方依赖。

## 18. 数据与迁移策略

从 v1.2.0 起预计需要提升本世存档版本；任何升级必须：

1. 保留 v1～v5 旧存档迁移；
2. 不从旧日志猜测玩家从未记录过的装备/因果/人生经历；
3. 新字段缺失时只补安全默认值；
4. 未知 ID、越界数量、非法层级必须拒绝或规范化；
5. 导入旧档后核心凡界/仙界状态不应被改变；
6. 轮回册继续与本世存档分离；
7. 每次 schema 升级增加专门迁移测试。

---

## 19. 发布与质量底线

每个小版本都必须独立完成：

`实现 → 单元测试 → 压力/状态机测试 → build → release 校验 → 浏览器验收 → 截图检查 → ACCEPTANCE 文档 → GitHub 线性提交 → 远端 SHA 核对`

任何版本未通过，不得把后续版本混进其提交。

生产包继续遵守：

- 10 MB 平台上限；
- 内部目标 3 MB；
- 不加入外部网络请求；
- 不加入音频大文件；
- 不加入第三方字体；
- 不把测试、截图、缓存和开发工具打入 ZIP。

---
