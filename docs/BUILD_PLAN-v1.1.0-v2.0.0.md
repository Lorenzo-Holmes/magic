9. 保存真实测试数字，后续版本只能报告实际结果。

## 2. 共同工程规则

### 2.1 文件边界

优先拆分模块，不继续把所有逻辑塞入 `src/app.js` 与 `src/engine.js`。

新增生产 JS 时必须同步更新：

- `index.html` 脚本加载顺序；
- `tools/production-files.cjs` 白名单；
- build / release 校验测试；
- README 工程结构。

### 2.2 RNG

任何掉落、事件、炼丹、灵兽、秘境随机都必须使用游戏现有可复现随机流或明确的新子随机流。

禁止：

- UI render 时消耗 RNG；
- 刷新页面重抽；
- 打开面板重抽；
- 动画回放再次掷随机数。

### 2.3 状态机

任何新系统都必须有：

- 合法入口；
- 合法退出；
- 中断/刷新恢复；
- 重复点击保护；
- 非法状态输入保护；
- 导入/迁移验证。

### 2.4 UI

保持手机竖屏优先。

必测视口：

- 320
- 360
- 390
- 430
- 768
- 1280

不得出现：

- 横向滚动；
- 主要按钮被底部导航遮挡；
- 对话框超屏无法关闭；
- 重要数值只有颜色区分；
- `prefers-reduced-motion` 下功能失效。

### 2.5 音频

继续使用 `src/audio.js` 的 Web Audio 架构。

不加入 MP3/WAV/外链音频。所有新增音效必须：

- 用户真实交互后才启动 AudioContext；
- 可以单独关闭；
- 页面隐藏时暂停；
- 不影响状态 RNG；
- 播放失败不阻塞玩法。

### 2.6 包体

- 内部目标 < 3 MB；
- 平台硬上限 < 10 MB；
- 资源优先 CSS/SVG/程序合成；
- 不引入运行时第三方包。

## 6. v1.4.0「九州历练」执行卡

### 新模块

`src/combat.js`

### 技术原则

战斗逻辑与表现事件分离：

```text
state + enemy + action
→ resolveCombat()
→ { result, stateDelta, replayEvents[] }
→ 一次性提交 stateDelta
→ UI 仅播放 replayEvents
```

### 首版表现事件

- encounter
- player-hit
- enemy-hit
- crit
- guard
- trigger
- devour
- defeat
- victory
- drop

### 验收

- 跳过动画与完整播放得到完全相同存档；
- 刷新不重复结算；
- R≥2 必胜规则继续成立；
- reduced-motion 立即显示战斗摘要；
- 战斗回放不会永久无限累积在存档。

## 16. 每个版本固定发布流程

每完成一个版本，按顺序执行：

### A. 版本与文档

1. `package.json` bump 到当前版本；
2. README 顶部和当前系统更新；
3. `docs/PROTOTYPE_DESIGN.md` 增加当前版本约定；
4. 新建 `docs/REVIEW-vX.Y.Z.md`；
5. 新建 `docs/ACCEPTANCE-vX.Y.Z.md`。

### B. 测试

```sh
npm test
npm run test:final
npm run build
npm run verify:release
npm run test:browser
```

如某版本只改表现层，`test:final` 仍运行一次作为主线回归证据。

### C. 人工截图检查

检查浏览器 QA 输出中的：

- 首页；
- 当前新增系统主页面；
- 一个窄屏；
- 一个桌面宽屏；
- 一个重大事件状态；
- reduced-motion（涉及动画版本）。

### D. 发布

1. 获取远端当前 SHA：

```sh
gh api repos/Lorenzo-Holmes/magic/git/ref/heads/main --jq .object.sha
```

2. 确认它等于上一版本刚刚核验过的 HEAD；
3. 使用：

```sh
node tools/publish-version.cjs <expected-parent-sha> "feat: wo-yu-fei-sheng vX.Y.Z"
```

4. 检查 `release/push-vX.Y.Z.json`；
5. 再查询远端 HEAD，必须等于记录的 commit；
6. 只有远端核对成功，当前版本才标记完成；
7. 然后才开始下一版本。

### E. 禁止

- 禁止 force push；
- 禁止覆盖远端无关文件；
- 禁止跳过失败版本去推下一版；
- 禁止把后续版本半成品混进当前提交；
- 禁止声称“已部署/已推送”而没有真实 SHA。

## 17. 最终部署

全部计划版本执行到本会话实际能够完成的最后一个绿色版本后：

1. 再跑完整测试矩阵；
2. 重新构建最新 ZIP；
3. 核验远端 HEAD；
4. 执行 Cloudflare 部署：

```sh
npm run build
npm run deploy
```

5. 对线上入口做最少一轮真实浏览器 smoke；
6. 最终报告真实线上版本、远端 SHA、ZIP SHA-256、测试数量和任何未完成项。

不为每个中间小版本重复 Cloudflare 部署，GitHub 保留每版线性恢复点，最终最新稳定版再部署。

## 18. 阻塞处理

只有以下情况算真实外部阻塞：

- DevSpace 对工作区失去必要权限；
- GitHub 身份失效且无法读取/推送；
- Cloudflare 身份失效；
- 平台本身拒绝当前文件类型或包体且无本地可行替代；
- 用户提供的外部资源缺失且该资源是明确硬依赖。

代码错误、测试失败、布局问题、迁移问题、包体问题都不是“询问用户是否继续”的理由，应在当前会话自行修复并重测。

如果真实外部阻塞发生：停止在最后一个已经远端验证的绿色版本，不污染下一版本，并把具体阻塞、已完成 SHA 和恢复入口写入新的 `docs/CONTINUATION-*.md`。
