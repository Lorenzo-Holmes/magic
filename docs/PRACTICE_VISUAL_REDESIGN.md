# 修行页视觉重构：听松静室

状态：v3.0.2 本地设计候选。没有推送 main，也没有部署 Cloudflare；视觉确认未代填。

## 需求判断

用户要的是接近《一念逍遥》修炼体验的游戏界面，不是更多仙山大图、浮岛建筑或装饰图标。本次只调整修行入口及其必要的导航文案，保留山海、行囊、人物、丹器和后续章节的玩法与存档。

应分清两个不同页面：洞府总览是功能导航，修炼室是修士、内景、修为和吐纳的主舞台。v3.0.1 把五处建筑导航当成修行页，导致真正的闭关与破境被挤到上下角落。此次选择“修炼室”而不是“洞府总览”作为一级入口。

## 线上问题与处理

| 观察到的问题 | 本轮处理 |
| --- | --- |
| 山景、贴上去的建筑与底图原有建筑重复，近景石台重复，透视和比例不统一 | 修行页撤下整屏洞府背景与五个建筑层，变为独坐修炼场景；不是继续加滤镜修饰原来的浮岛布局 |

| 修为在顶部，根基在角落，主要动作和当前目标又在不同区域 | 修为、百分比、根基、下一境界和当前缺项集中到动作上方 |

| 桌面两侧重复放大同一山景，纹理抢夺注意力 | 仅在修行页隐藏外层重复山景，用深墨背景衬托竖向游戏舞台 |

## 新版布局

顶部是单行境界、战力和设置；其下用一条细资源栏显示道龄/寿元、元气、盘缠、行粮。主场景中保留明确的独坐修士与上方内景，避免同时堆叠多个建筑和人物。左侧“服丹”打开真实丹药分类，右侧“洞府事务”展开山门、丹器、灵兽和命册。

下方先显示真实修为进度，再显示下一境界和根基。中间的主按钮在引擎允许时由“闭关”切换为“破境”；左侧是连续闭关，右侧是寻机缘。三者明确显示收益、耗时或停止条件，不设置虚假的每秒产出。妖王、天地印证和根基不足只在对应阶段显示。

最下方保留当前目标及可展开的教学指引。强制事件继续使用原来的选择与结算文本，在独立层中可滚动阅读，不允许背景修炼操作绕过待处理事件。

## 视觉规格

修行室采用墨蓝黑、雾灰与少量青白光，不把所有页面都改成深色。普通态以青白表现安静吐纳，可破境态只在主要操作上使用温金。内景随现有境界改变表现，不新增修法/炼体分支或新的数值系统。

正文与费用最低 12 CSS px，常用操作不低于 44×44 CSS px。小屏保留资源栏、进度和主要操作，减少场景高度和辅助题字。背景允许在明确的裁切容器中放大；文字、动作和导航不跟随背景一起缩放。

一级导航的第一项改称“修行”，仍沿用 `practice` ID；其它三个导航及其数据关系不变。当前皮肤只作用于 `.practice-room` 及修行状态下的底栏，不改写全局弹窗的状态逻辑。

## 美术与代码边界

本轮没有继续批量生图。为先验证正确构图，重新使用本项目已有的 `assets/art/retreat-v2.1.webp`：它本身含坐姿修士，采用局部取景和墨蓝色调，而不是再次使用满屏楼阁。该图是项目已有生成素材，不是《一念逍遥》截图或拆包纹理。

这仍是固定坐姿背景，不是骨骼动画、动态换装或精细的正面人物立绘。上方内景为轻量表现层，不声称已经还原原作丹田动画。当前候选的重点是场景主次、修炼动作和可读性；美术相似程度仍需用户看运行画面确认。

最终分层美术应另行按以下规格制作，而不是继续生成整屏金色仙宫：低细节近景洞天底图（不含角色/平台/文字）、独立盘膝人物（墨线与青灰素袍）、同透视石台与少量香炉/松枝、单色气息与丹田状态层。当前候选尚未交付这四组新母资产；也没有把本次参考演示中的人物或丹田切图拿来使用。现有 82 个资源在其它页面继续使用，不在修行页全量堆叠。

实现文件：`src/ui-v3/cave.js`、`src/ui-v3/practice.css`。注册名称保留 `CaveWindow` 以避免无意义重命名。修行页不再调用洞府镜头缩放；地图原有镜头不变。图片失败时保留纯色背景及全部操作，窗口退出时释放局部监听。

没有复制原作 Lua、Prefab 或字体。所有实际动作继续调用 `FSEngine.transition`，保留 revision、本世与轮回册存档。CSS 动画不能增加修为或重复结算，减少动态效果时只停表现。
